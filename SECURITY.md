# Security Policy

## Reporting security issues

**Do NOT open a public issue for security-sensitive findings.**

If you have found a vulnerability affecting the Gonka network (protocol, nodes, DevShards, bridge, contracts) or the DevNet infrastructure operated by this project:

1. Report privately via [GitHub Security Advisory](../../security/advisories/new) on this repository, **or**
2. Email **paranko@dahl.global** with the affected component, reproduction steps, and your impact assessment.

We aim to acknowledge reports within 48 hours.

## Disclosure process

Per the approved proposal ([discussion #1388](https://github.com/gonka-ai/gonka/discussions/1388), governance proposal #82), the Test Lab follows public-by-default reporting with one exception:

- Security-sensitive findings are reported **privately to the Gonka Core Team first**.
- A public placeholder issue may be created where appropriate, without exploitable details.
- Full details are disclosed after remediation or an agreed disclosure window.

## Scope

Findings that arise from Test Lab activities: protocol upgrade validation, DevShard releases, inference flows, host/broker operations, and Community DevNet behavior.

For vulnerabilities in Gonka core components discovered outside Test Lab activities, you can also report directly to the [gonka-ai/gonka](https://github.com/gonka-ai/gonka) maintainers.
