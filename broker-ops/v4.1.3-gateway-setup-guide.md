# Devshard gateway 4.1.3 — broker guide

From any running gateway to a running 4.1.3 gateway with a public
accounting link. One pass, top to bottom.

4.1.3 speaks protocol v4.1. Route prefix `/devshard/v4.1`, session version
`v4.1`. Hosts answer 404 to any other prefix.

Release: [`release/gateway/v4.1.3`](https://github.com/gonka-ai/gonka/releases/tag/release/gateway/v4.1.3)
(gonka-ai/gonka, 2026-10-05).

Use this image:

```
ghcr.io/gonka-ai/devshard-gateway:mainnet-v0.2.15-v4.1.3
```

**Plan:** new container on a **fresh volume** next to the one you are leaving
→ settings → mint on `/devshard/v4.1` → smoke → switch the front → confirm
every escrow is `v4.1` → expose accounting.

---

## 0. Before you start

You need:

- `GATEWAY_API_KEY` — the key your clients use (any string you choose).
- `DEVSHARD_ADMIN_API_KEY` — admin key (another string; keep it off the internet).
- `DEVSHARD_PRIVATE_KEY` — hex private key of the wallet that pays for escrows.
  Balance: a few GNK per escrow, one escrow per model minimum.
- A JSON-RPC endpoint. Public `https://rpc.gonka.gg/chain-rpc/` works
  (**trailing slash required**). If you run your own node, use it.

Pick the **window**: Inference phase only, not PoC / cPoC, with enough blocks
left before `next_poc_start` to mint and smoke (say ≥ 500 blocks).

```bash
curl -sS https://rpc.gonka.gg/v1/epochs/latest \
  | jq '{phase, epoch: .epoch_stages.epoch_index, next_poc: .epoch_stages.next_poc_start, height: .block_height}'
```

## 1. Container

```bash
docker pull ghcr.io/gonka-ai/devshard-gateway:mainnet-v0.2.15-v4.1.3
```

Add to your compose. Names and host ports below are an example. The gateway
you are leaving keeps its own service, volume, and ports. Do not override
image defaults that this block does not list.

```yaml
  devshardctl-v413:
    image: ghcr.io/gonka-ai/devshard-gateway:mainnet-v0.2.15-v4.1.3
    restart: unless-stopped
    environment:
      DEVSHARD_PORT: "8080"
      DEVSHARD_API_KEYS: ${GATEWAY_API_KEY}
      DEVSHARD_ADMIN_API_KEY: ${DEVSHARD_ADMIN_API_KEY}
      DEVSHARD_PRIVATE_KEY: ${DEVSHARD_PRIVATE_KEY}
      DEVSHARDS_JSON: "[]"
      DEVSHARD_CHAIN_ID: gonka-mainnet
      DEVSHARD_CHAIN_RPC: https://rpc.gonka.gg/chain-rpc/
      DEVSHARD_CHAIN_GRPC: none                     # public RPC covers tx + query
      DEVSHARD_PUBLIC_API: https://node3.gonka.ai
      DEVSHARD_ROUTE_PREFIX: /devshard/v4.1         # not /devshard/v5, not /devshard/v4.1.3
      DEVSHARD_STORAGE_DIR: /root/.devshardctl
      DEVSHARD_TX_GAS_LIMIT: "700000"
      DEVSHARD_CAPACITY_AWARE_LIMITS: "on"
      DEVSHARD_POC_REQUEST_MODE: relaxed
      DEVSHARD_STATS_ENABLED: "true"                # accounting ledger on :9091
      DEVSHARD_ESCROW_ROTATION_SETTLEMENT_ENABLED: "false"   # do not turn this on
    volumes:
      - devshard_v413_data:/root/.devshardctl      # NEW volume — never reuse the old one
    ports:
      - "127.0.0.1:18088:8080"                     # API + admin: loopback only
      - "127.0.0.1:19088:9091"                     # accounting: loopback only, NOT the old port

volumes:
  devshard_v413_data:
```

`18088` and `19088` are examples. Do not bind this container to a host port
the old gateway already publishes. Both may run until you have confirmed the
new slot.

`DEVSHARD_ESCROW_ROTATION_SETTLEMENT_ENABLED` is automatic settlement. Leave
it `false`. Do not set it to `true`. Settlement stays a manual step you run
yourself.

Own chain node with gRPC? Point `DEVSHARD_CHAIN_RPC` / `DEVSHARD_CHAIN_GRPC`
at it instead of `none` + public RPC. Do not mix the two.

```bash
docker compose up -d devshardctl-v413
export A=http://127.0.0.1:18088 H="Authorization: Bearer $DEVSHARD_ADMIN_API_KEY"
curl -fsS $A/v1/status -H "$H" | jq .runtimes
curl -fsS http://127.0.0.1:19088/api/v1/epochs | jq .   # {"epochs":[]} — ledger is empty, fine
```

## 2. Settings

A fresh `gateway.db` starts with every model **`admin_only`** and a
`default_model` you may not serve. Clients would get:

```text
401  model "<id>" requires an admin API key
```

Read, edit, write back the **whole** document (no PATCH):

```bash
curl -fsS $A/v1/admin/settings -H "$H" > settings.json
```

Change only `default_model` and, on each model you serve, `access_mode`.
Leave every other field at the value the image wrote, including concurrency
and token caps.

```json
{
  "default_model": "<MODEL_A>",
  "model_limits": [
    { "model_id": "<MODEL_A>", "access_mode": "api_key" },
    { "model_id": "<MODEL_B>", "access_mode": "api_key" }
  ]
}
```

Keep the other keys already present on each `model_limits` object. One entry
per model you serve.

- `access_mode`: `open` / `api_key` / `admin_only`.
- In `escrow_rotation`, `settlement_enabled` must stay `false`. Do not enable
  automatic settlement.

```bash
curl -fsS -X POST $A/v1/admin/settings -H "$H" -H 'Content-Type: application/json' --data-binary @settings.json
curl -fsS $A/v1/admin/settings -H "$H" | jq '{default_model, model_limits, escrow_rotation}'
```

## 3. Mint escrows

Clients are still on the old gateway; nothing changes for them yet.

```bash
curl -fsS -X POST $A/v1/admin/escrows -H "$H" -H 'Content-Type: application/json' -d '{
  "amount": 5000000000,
  "model_id": "<MODEL_A>",
  "private_key_env": "DEVSHARD_PRIVATE_KEY",
  "route_prefix": "/devshard/v4.1",
  "register": true
}'
sleep 12
# repeat per model / per extra escrow
```

- `amount` is ngonka: `5000000000` = 5 GNK, `2500000000` = 2.5 GNK.
- **Always** pass `model_id` and `"route_prefix": "/devshard/v4.1"`. Without
  the prefix the escrow lands on the default slot. `protocol_version` in the
  body is ignored. `/devshard/v5` and `/devshard/v4.1.3` are the wrong slot.
- One tx at a time, 8–12 s apart — a second tx too soon dies on account query.
- One escrow per model is enough to start; more = redundancy. Each escrow
  carries a nonce budget (~20k) and a GNK balance; when either runs out it
  stops serving and you mint another.

Wait ~30 s, then check:

```bash
curl -fsS $A/v1/status -H "$H" | jq '{models: .capacity.models,
  escrows: [.devshards[]? | {id, model, active, session_version, nonce}]}'
```

Every offered model should show `routable: true`. Every escrow must show
`session_version: "v4.1"`. If any row is `v5`, or anything else, do not
switch traffic. The mint used the wrong prefix or this process is still on
the old volume.

**Tx hash but `escrow not found` / escrow missing from the list?** The chain
object exists, the gateway lost the register. Do **not** mint again. Import:

```bash
curl -fsS -X POST $A/v1/admin/devshards -H "$H" -H 'Content-Type: application/json' -d '{
  "id": "<ESCROW_ID>", "escrow_id": "<ESCROW_ID>", "model_id": "<MODEL_A>",
  "private_key_env": "DEVSHARD_PRIVATE_KEY", "route_prefix": "/devshard/v4.1",
  "register": true, "storage_path": "escrow-<ESCROW_ID>"
}'
curl -fsS -X POST $A/v1/admin/devshards/<ESCROW_ID>/activate -H "$H"
```

`409 already active` = it was loaded after all.

## 4. Smoke with the client key

Admin-key 200 proves nothing. Use the key your clients use, per model, against
the **new** port:

```bash
curl -fsS -X POST $A/v1/chat/completions \
  -H "Authorization: Bearer $GATEWAY_API_KEY" -H 'Content-Type: application/json' \
  -d '{"model":"<MODEL_A>","max_tokens":16,"messages":[{"role":"user","content":"pong"}]}'
```

401 here → back to §2 (`access_mode`). `unsupported model` → no active escrow
for that model (§3). `409 session version conflict` → the escrow is not on
`/devshard/v4.1`.

## 5. Switch client traffic

Repoint your front (proxy `GATEWAY_URL`, nginx `upstream`, …) at the new
gateway. Which address depends on where the front runs — use the same rule
for the accounting upstream in §6:

| Front runs… | Gateway API upstream | Accounting upstream |
|---|---|---|
| in the same Docker Compose network | `http://devshardctl-v413:8080` | `http://devshardctl-v413:9091` |
| on the host (or another network) | `http://127.0.0.1:18088` | `http://127.0.0.1:19088` |

`GATEWAY_URL` includes the API prefix, so the compose-network value is
`http://devshardctl-v413:8080/v1`. Do not leave it on the previous service
name or the previous host port.

### Confirm the slot

After the front is repointed, read status from the URL the front now uses.
Every escrow must be protocol v4.1:

```bash
curl -fsS http://127.0.0.1:18088/v1/status -H "$H" \
  | jq '[.devshards[]? | .session_version] | unique'
```

Expect:

```json
["v4.1"]
```

Stop if the list is empty, or if it contains `v5` or any other value. Clients
would still be on the gateway you are leaving, or this process minted onto
the wrong prefix. Fix that before sending traffic.

Also check the front itself, not only the new container. A healthy old
container keeps answering if one upstream was left behind:

- proxy `GATEWAY_URL` → `http://devshardctl-v413:8080/v1` (or `http://127.0.0.1:18088/v1`)
- accounting upstream → `devshardctl-v413:9091` or `127.0.0.1:19088`
- no nginx `proxy_pass` / Caddy `reverse_proxy` still aimed at the old port

## 6. Public accounting link

The ledger listens on container port `:9091`. No authentication, no
compression, read-only. Do not publish that port to the internet. Proxy the
host port you chose (`19088` in the example):

1. allow only `GET`;
2. forward only `/api/v1/epochs…`;
3. gzip the responses.

| GET | Content |
|-----|---------|
| `/api/v1/epochs` | per-epoch index: nonces, dispositions, misses |
| `/api/v1/epochs/{n}/participants` | per host × model |
| `/api/v1/epochs/{n}/events` | raw per-nonce events |
| `/api/v1/epochs/{n}/events/{participant}` | same, one host |

```
https://<your-domain>/api/v1/accounting/epochs…  →  http://127.0.0.1:19088/api/v1/epochs…
```

Inside the Compose network use `devshardctl-v413:9091` instead of
`127.0.0.1:19088`. The old gateway's ledger is a different process. Do not
keep the public URL on that port.

### nginx

```nginx
location ^~ /api/v1/accounting/epochs {
    limit_except GET { deny all; }
    rewrite ^/api/v1/accounting/(.*)$ /api/v1/$1 break;
    proxy_pass http://127.0.0.1:19088;
    proxy_set_header Host $host;
    proxy_read_timeout 60s;
    gzip on;
    gzip_proxied any;
    gzip_types application/json;
    gzip_min_length 1024;
    add_header Cache-Control "public, max-age=30";
}
```

### Caddy

```caddyfile
handle_path /api/v1/accounting/* {
    @epochs {
        method GET
        path /epochs /epochs/*
    }
    handle @epochs {
        encode gzip
        rewrite * /api/v1{uri}
        reverse_proxy 127.0.0.1:19088
    }
    respond 405
}
```

`handle_path` strips `/api/v1/accounting`, leaving `/epochs…`; the rewrite
puts `/api/v1` back so the root query reaches `/api/v1/epochs` without a
trailing slash.

### Verify

```bash
D=https://<your-domain>
curl -fsS "$D/api/v1/accounting/epochs" | jq '.epochs[] | {epoch_index, assigned_nonces}'
E=$(curl -fsS "$D/api/v1/accounting/epochs" | jq -r '.epochs[-1].epoch_index // empty')
[ -n "$E" ] && curl -sS -o /dev/null -w 'participants: %{http_code} %{size_download}B\n' \
  -H 'Accept-Encoding: gzip' "$D/api/v1/accounting/epochs/$E/participants" \
  || echo 'ledger still empty — retry after some traffic'
curl -sS -o /dev/null -w 'POST must be 405/403: %{http_code}\n' -X POST "$D/api/v1/accounting/epochs"
curl -sS -o /dev/null -w 'admin must NOT be reachable: %{http_code}\n' "$D/v1/admin/settings"
```

Base URL for the dashboard: `https://<your-domain>/api/v1/accounting`.

## Pitfalls

**Wrong slot.** `DEVSHARD_ROUTE_PREFIX` or mint `route_prefix` set to
`/devshard/v5`, `/devshard/v4.1.3`, or omitted. Escrows register on another
protocol. `session_version` will not be `v4.1`. Hosts answer `409 session
version conflict` or `404`. Fresh volume, prefix `/devshard/v4.1` only.

**Front still on the old gateway.** The new container is healthy and the old
one still receives `GATEWAY_URL`, the nginx upstream, or the accounting
proxy. §5, both the table and the confirm step.

**Reusing the old volume.** The new process loads the previous gateway's
escrows and prefix. New volume `devshard_v413_data`.

**Traffic switched, no escrows.** `unsupported model` for everything. Mint
first (§3), switch last (§5).

**`admin_only`.** The first 401 after a "successful" mint. §2.

**`DEVSHARD_CHAIN_GRPC` left unset.** The binary persists `localhost:9090`
into `gateway.db` and probes a dead endpoint forever. Set `none` on public RPC.

**Public RPC returning HTML.** `invalid character '<'` on account/escrow
queries = the RPC answered an nginx error page or a redirect (a missing
trailing slash used to `301` and turn the POST into a GET; keep the slash
even if the endpoint accepts both today). Use `https://rpc.gonka.gg/chain-rpc/`
or your own node.

**Minting in PoC / right before `next_poc`.** Validator set is moving; wait
for Inference.

**Binding the new ledger to the old host port.** The old gateway is probably
already on that port. Use another loopback port until you have confirmed
`session_version` is `v4.1` and moved the public accounting URL.

**Automatic settlement.** Do not set `escrow_rotation.settlement_enabled` or
`DEVSHARD_ESCROW_ROTATION_SETTLEMENT_ENABLED` to `true`. Leave settlement off
and run it manually when you mean to.

**`GET /v1/status` with a single escrow** may render as a legacy card without
`.devshards[]`. Check `/v1/admin/devshards` or list the ids you minted. Still
require `session_version` `v4.1` on each id.

---

## Rollback

Point the front back at the previous gateway, and point accounting back at
its port. The 4.1.3 escrows stay on chain and in the new gateway's volume.
Do not `compose down` or remove volumes to "undo".
